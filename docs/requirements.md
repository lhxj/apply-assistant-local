# 网申助手（本地版）· 需求文档 v1

> 状态：需求已确认，进入开发。
> 本文件是开发的唯一依据；变更需双方确认后更新本文档。

## 1. 定位与边界

把「填网申表单」这件事完全本地化：一份本地简历快照 + 按服务商分层的规则库 + 一键填写。

**做：**
- 本地简历快照（唯一信息源），可编辑、可从页面抓回更新
- 按服务商（Moka / 北森 / 牛客 / 通用兜底）分层的规则匹配
- 一键填写、更新快照、更新规则三个闭环
- Chrome + Edge，Manifest V3，无构建步骤，加载解压缩扩展即可用

**不做（v1 明确排除）：**
- 任何服务端依赖、联网、AI 智填、登录/账号体系
- 附件类字段（简历 PDF、证件照、成绩单上传）——遇到文件框跳过并在报告中提示手动上传
- 多份简历/多版本快照（数据结构留扩展位）
- 服务商位置快照（"照抄上次这家表单"）——v1.5 再议
- 预览模式（只识别不写入）——按用户决定不做，直接填入
- 跨设备同步（不用 chrome.storage.sync）

## 2. 场景

秋招投递：每家公司网申都要重复填写 10–30 分钟的简历表单。插件的价值不在"一次填对"，而在**规则随投递过程沉淀、越用越准**。

## 3. 核心概念

### 3.1 简历快照（唯一信息源）

所有服务商共用一份。时间统一存 `YYYY.MM`（可选精确到日 `YYYY.MM.DD`），在职/在读存字符串 `"至今"`。

```
basicInfo:    姓名/性别/手机号/邮箱/出生日期/证件类型/证件号码/所在地/
              最高学历/工作经验/政治面貌/籍贯
intent:       当前薪资/期望薪资/期望城市/期望职位
education[]:  学校/专业/学历/入学时间/毕业时间/是否全日制/排名
work[]:       公司/职位/开始时间/结束时间/工作内容
internship[]: 公司/职位/开始时间/结束时间/工作内容
project[]:    项目名称/职责/开始时间/结束时间/项目描述/项目中职责
language[]:   语言类型/掌握程度/听说/读写
award[]:      奖项名称/获奖时间
selfEval:     自我描述
customFields: { 任意键: 值 }   ← 学回的新字段进这里
```

### 3.2 字段寻址三元组

一个页面输入框的唯一地址 = **（区块 section，条目序号 index，标签 label）**。

实测 Moka 页面证明其必要性：同名标签既跨区块冲突（`公司名称` 同时属于工作经历和实习经历），又在区块内因多条目重复（2 条教育经历各有 `学校名称`）。

### 3.3 规则库（JSON 数据，运行时可生长）

分层合并：`全局规则` ← `服务商规则` 覆盖/增量。

- `aliases`：标签 → 快照路径（平铺字段用）
- `sectionAliases`：区块标题 → 快照区块名
- `scopedAliases`：区块内标签 → 区块条目字段名（解决同名冲突的主力）
- `optionValueAliases`：快照值 → 页面选项文字（如 `advanced` → `熟练`）
- 服务商规则另含：URL 识别模式、DOM 语义（区块标题/字段标签/控件的选择器，一律用 class 前缀匹配，因为目标站 class 名带发版哈希）

"更新规则" = 用户从未匹配格子弹出的快照字段树里点选一个路径 → 给当前服务商的 scopedAliases/aliases 增加一条。纯数据追加，不需要改代码。

### 3.4 服务商写入适配

同一份快照数据，写法按服务商适配，差异全部沉淀在适配器层：
- Moka 年月四段下拉：`2021.07` 拆成年/月两个下拉
- 北森 `YYYY-MM-DD` 文本框：格式化，快照只有年月时补 `01` 并在报告提示"请核对日期"
- 自绘下拉（非原生 select）：点开 → 按文字（经 optionValueAliases 转换）找选项 → 点击

## 4. 功能需求

### F1 一键填写
1. 识别服务商（URL 模式 + 页面特征），加载合并后的规则
2. 扫描页面全部可见控件 → 三元组寻址
3. 规则匹配生成填写计划；未匹配/低置信格子进报告
4. **已有值的格子一律跳过**（Q16）
5. 条目不够时自动点「添加」补齐到快照条数（Q17，上限=快照条数）
6. 拟人节奏写入：每格间隔约 100ms，显示进度，可中途取消（Q19）
7. 完成后出报告：`已填 N / 跳过(已有值) M / 未匹配 K`，未匹配项可发起"更新规则"

### F2 编辑快照
独立编辑页（`chrome-extension://<id>/editor/`）：按 schema 结构生成表单，支持条目增删、空值高亮、导入/导出 JSON（合并或替换）。

### F3 更新快照
填完/手填完后一键整页抓回（Q14-a）：所有能识别三元组位置的格子按当前页面值写回快照（覆盖旧值）；识别不了位置的进 customFields 候选，用户勾选确认。

### F4 更新规则
报告中的未匹配格子 → 点选 → 弹出快照字段树 → 选定目标路径 → 给当前服务商追加别名规则，即时生效，持久化到 storage。

### F5 悬浮球面板
页面右下角悬浮球，点击展开小面板（白+绿清新风格）：
- 显示识别出的服务商（Moka / 北森 / 牛客 / 通用）
- 按钮：一键填写 / 更新快照 / 更新规则入口 / 编辑快照
- 填写进度与结果报告区

## 5. 技术约束

- Manifest V3，纯原生 JS，无框架无构建；改文件 → 重载扩展 → 刷新页面即生效
- 数据全部存 `chrome.storage.local`（快照 + 规则库 + 设置）
- 选择器只允许 class **前缀**匹配（`[class*="filed-title-"]`），禁止写死哈希后缀
- content script 在所有页面注入但自启动门槛极低：未识别到服务商/表单密度不足时立即退出，零干扰
- 实测基线（中控信息 · Moka）：10 个区块、75 个可见控件、5 种控件类型（文本/多行文本/自绘下拉/年月四段时间/勾选框）
