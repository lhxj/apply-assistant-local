# Moka / 北森真实页面 DOM 基线

生成日期：2026-09-13

## 观察范围与隐私边界

本次使用 Codex 内置浏览器中用户已经打开的两个真实页面做只读检查：

- Moka：`app.mokahr.com` 的上海非凸智能科技有限公司职位申请页。
- 北森：`flyaitalent.zhiye.com` 的泛联新安校招投递页。

记录依据是当前渲染页面的可访问性树（它是 DOM 的只读投影）以及页面结构中可见的标签/控件关系。没有读取或写入个人字段值，没有点击候选项，没有上传文件，没有点击暂存、预览或提交。文档只保留结构和控件类型，不记录手机号、邮箱、token、userId 或其他个人数据。

可访问性树会把部分自绘控件显示成“text field + content list + image”，也可能隐藏真实的内部 input 类型。因此本文件用于第一轮扫描器基线，不等同于完整平台 Adapter 规范。

当前页面的字段标题与控件按“标题文本 → 包裹控件容器”的关系排列。Moka 代码中已有的 class 前缀选择器（`apply-block-*`、`basic-block-*`、`block-title-*`、`filed-title-*`/`title-*`）能够覆盖这类区块和字段标题，但字段 class 不是稳定业务 ID，不能只按 class 猜字段语义。

### 控件基线

| 区域/字段示例 | 只读观察到的控件形态 | 第一轮处理 |
| --- | --- | --- |
| 意向工作城市 | 自绘选择框，AX 中表现为可设置的 text field 和箭头/弹层提示 | 作为 select/search-select 候选；必须打开后精确点击候选 |
| 姓名、所在地、最近公司、当前薪资、期望薪资、期望城市 | 普通可设置 text field | 可按文本规则处理，写后回读 |
| 手机号码 | 国家区号容器 + 手机号输入框，旁边有校验提示 | 只映射 `手机号码`；不把同名“联系电话”跨 section 映射 |
| 邮箱 | 普通 text field | 文本写后回读 |
| 性别、工作经验、最高学历、语言掌握程度/听说/读写 | 自绘下拉/搜索选择容器 | 不使用模糊包含匹配；候选不唯一时跳过 |
| 出生日期（年龄） | 日期相关输入区域 | 由标签语义确认 date，不按下拉数量推断 |
| 工作/实习/项目的起止时间 | 起点年、起点月、终点年、终点月四个自绘选择控件，中间有分隔符，并有“至今”复选框 | 只有明确的“起止时间/至今”语义才识别为 range |
| 教育背景的就读时间 | 起点年/月和终点年/月四个自绘选择控件 | 由 `就读时间` 语义识别为 range，不采用“4 个 select 就是 range”的通用猜测 |
| 获奖时间 | 两个自绘年月选择控件 | 由 `获奖时间` 语义识别为 date/年月组 |
| 工作职责、项目描述、项目中职责、自我描述 | entry area/textarea | 作为 textarea，写后回读 |
| 至今、同步更新在线简历 | checkbox | “至今”只能随明确的经历结束值处理；“同步更新在线简历”保持 manual-only |
| 预览并提交 | button | 不进入自动填写计划 |

当前 Moka 页面没有在可见页面中观察到文件上传控件或 radio group；Excel 中的 Moka 字段也没有单选/文件行。Scanner 仍需保留通用 radio/file 识别，以便同平台其他职位页面变化时安全降级。

### 重复经历与添加按钮

工作经历、教育背景、实习经历、项目经验、语言能力和获奖经历都表现为“区块标题 + 添加按钮 + 至少一个经历容器”。可见添加按钮的文本为“添加”，并紧邻对应区块标题。经历容器内部再按字段标题组织控件。

Round 1.1 起 Generic `ensureItemCount` 不再由主流程调用，当前只扫描并填写页面已经存在的经历块。点击添加属于修改页面结构的动作，本次基线检查没有点击它；待 Moka/北森 Adapter 完成真实验证后再考虑开启，并且开启前仍需重新扫描，不能复用旧索引。

### 下拉和日期结论

Moka 的下拉不是可靠的原生 `<select>` 值赋值场景，而是自绘选择框。当前 AX 树显示控件和弹层入口，但没有在只读检查中展开候选列表。因此 Writer 必须：

1. 打开控件；
2. 在可见候选中寻找唯一的归一化精确文本；
3. 只有唯一候选才点击；
4. 回读控件显示值，匹配后才记为 `verified`。

日期选择也遵守同一规则。不能因为容器里出现两个或四个选择控件就直接判定 date/range。

### 控件基线

| 区域/字段示例 | 只读观察到的控件形态 | 第一轮处理 |
| --- | --- | --- |
| 简历文件、证件照 | 上传区域/上传文件入口，伴随图标和格式说明 | 识别为 `file`，只报告 manual，不打开文件选择器、不上传 |
| 姓名、手机号码、邮箱、期望月薪 | text field；手机号码另有地区选择容器 | 文本/手机号按标签处理，写后回读 |
| 性别、是否全日制、是否可提前实习 | 一组选项文本；实际 DOM 类型必须按 `input[type=radio]` 识别 | 识别为 radio；只在唯一选项匹配时点击并回读 |
| 出生日期、籍贯、最高学历、政治面貌 | 自绘选择框，AX 结构为“请选择 + content list + 可设置 field + 箭头图像” | 视为 search-select/自绘 select；需要真实点击唯一候选 |
| 教育经历的学历、开始时间、结束时间 | 同样的自绘选择/日期选择结构 | 不按 select 数量判断日期；结合标签语义 |
| 实习/项目/工作开始时间、结束时间、获奖时间、证书获得时间 | 自绘日期选择入口 | 记录为 date 候选；第一轮不写平台专用日期 Adapter |
| 实习内容、项目描述、获奖描述、工作职责、技能描述、证书描述 | entry area/textarea，并显示字数计数 | textarea；写后回读，超出格式或内容不猜测 |
| 至今 | checkbox，与结束时间同一经历容器相邻 | 只有快照明确为进行中时才考虑；不当作普通声明勾选 |
| 声明 | 独立 checkbox，旁边是完整的本人实际情况声明文本 | manual-only，不自动勾选 |
| 暂存、取消、预览并提交 | button | 不进入自动填写计划 |

### 重复经历与添加按钮

教育、实习、项目、获奖、工作、技能和证书均有重复经历容器。每个容器后面都有对应的添加入口，例如“添加 教育经历”“添加 实习经历”“添加 项目经历”等；AX 中入口表现为带 `_addButton` 的容器和文本。

重复块内部的 label、控件和字数提示是同一层级关系，不能用全页第几个 input 作为定位。每次添加后应重新扫描并重新计算 section 内的 `index`。本次只读检查没有点击任何添加按钮。

### Radio / file / select / date 结论

- **Radio**：可访问性树显示性别等选项文本，但浏览器 AX 投影不总是公开真实 input 类型。代码以 `input[type=radio]` 为主识别依据；未识别为 radio 时保持 `unknown`，不把它当普通文本输入。
- **File**：必须保留 `input[type=file]` 在扫描结果中，kind 为 `file`，并在 Matcher 中转为 manual；Writer 不调用 `setFiles`、不上传。
- **Search-select**：北森大量选择控件显示为“请选择 + content list + field + 箭头”，说明不能仅设置一个 input.value。必须真实打开并点击唯一候选。
- **Date**：个人出生日期、教育开始/结束日期及各经历时间均使用自绘日期入口。第一轮仅记录形态和安全降级规则，不把它们统一成完整日期 Adapter。
- **Select 多候选**：若可见列表中有多个同名候选，第一轮禁止自动选择；没有精确候选也跳过。

## 基线限制与第二轮入口

本轮读取了真实渲染结构，但没有为了取内部属性而注入脚本、修改页面或展开候选列表。需要第二轮继续验证的内容包括：北森每种 search-select 的候选层稳定定位、出生日期的年月/日期粒度、家庭/推荐人字段的 section scope、添加经历后的动态索引，以及提交前由用户确认的声明/隐私流程。
