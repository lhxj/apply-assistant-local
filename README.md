# 网申助手 · 本地版

把「填网申表单」这件事完全本地化的浏览器插件：一份本地简历快照 + 按服务商分层的规则匹配，一键填完各大招聘系统的重复表单。

**无联网 · 无登录 · 无 AI 智填 · 数据不出本机**

支持 Chrome / Edge（Manifest V3），无需构建，加载解压缩扩展即可使用。

## 为什么做这个

秋招投递时，每家公司都要在 Moka / 北森 / 牛客等系统里重填一遍同样的简历表单，每次 10–30 分钟。这个插件的价值不在"一次填对"，而在**规则随投递过程沉淀、越用越准**：遇到没匹配上的格子，现场点一下"学规则"，下次同服务商的表单直接命中。

## 功能

- **一键填写**：识别服务商 → 扫描表单 → 按规则匹配快照 → 拟人节奏写入（约 100ms/格，可取消）→ 写后回读验证。已有值的格子一律跳过，宁可少填不可填错
- **三元组寻址**：`(区块, 条目序号, 标签)` 唯一定位每个输入框 —— 「工作经历」和「实习经历」的"公司名称"永不串场；多条教育/获奖经历按序号各归各位
- **编辑快照**：独立编辑页，按 Schema v2 生成表单（基本信息/求职意向/教育/工作/实习/项目/语言/语言考试/获奖/技能/证书/家庭成员/推荐人/自我描述/自定义字段），支持导入导出 JSON
- **更新快照**：填完或手填完一页表单，一键整页抓回快照
- **更新规则**：未匹配的格子 → 点"学规则" → 在快照字段树里点选它是什么 → 规则立即生效并持久化，自动追加到当前服务商名下
- **重复经历安全模式**：当前只扫描并填写页面已经存在的经历块，不自动点击“添加”；待 Moka/北森 Adapter 完成真实验证后再开启自动补条目
- **安全降级**：不确定的控件、重复候选、文件、声明、隐私和提交都报告给用户，不自动猜测或操作

## 安装

1. 克隆本仓库
2. Chrome 打开 `chrome://extensions`（Edge 打开 `edge://extensions`），开启**开发人员模式**
3. 点**加载解压缩的扩展**，选择本仓库的 `extension/` 目录
4. 打开任意网申页面，点右下角绿色「申」悬浮球 → **编辑快照**，录入你的简历

## 使用

| 操作 | 说明 |
| --- | --- |
| 一键填写 | 扫描当前表单并按规则填入快照数据，完成后出报告（已填/跳过/失败/未匹配）；填写中按钮变为「取消填写」 |
| 更新快照 | 把当前页面的表单内容整套抓回快照（覆盖旧值） |
| 更新规则 | 列出本页每个格子的当前映射（归属当前服务商），点任意一行可修改；未匹配的格子在填写报告里也能直接「学规则」 |
| 编辑快照 | 打开快照编辑页 |
| 清空表单 | 清空本页表单的全部已填内容（含手填，操作前有确认） |

服务商按网址自动识别（Moka=`mokahr.com`，北森=`zhiye.com/italent.cn/beisen.com`，牛客=`nowcoder.com`，其余走通用规则），域名按完整主机名边界匹配；学到的规则自动归属当前服务商，与内置种子规则分层合并。

快照使用 `schemaVersion: 2`。`籍贯`、`户籍所在地`、`现居住地` 在 Schema v2 中是三个不同字段；历史 `basicInfo.hukou` 只保存在 `legacy.hukou`，需要手动确认，不会自动填入其中任何一个。

## 数据与隐私

- 全部数据（简历快照、规则库、设置）只存在 `chrome.storage.local`，插件**没有任何网络请求**
- 快照可通过编辑页导出 JSON 自行备份
- ⚠️ 导出的快照 JSON 包含个人敏感信息，**不要提交到公开仓库**（已在 `.gitignore` 中排除 `*.snapshot.json`）

## 工作原理

```
识别服务商(URL) → 扫描(字段容器/区块/条目序号/控件类型) → 规则匹配(全局别名 ← 服务商别名)
→ 生成填写计划 → 跳过已有值 → 拟人节奏写入(文本/自绘下拉/年月四段/勾选框) → 报告
```

- 规则库是纯 JSON（`extension/rules/seed.json` 为内置种子，运行时学的规则存 storage 的独立用户层）：
  - `aliases`：标签 → 快照路径（平铺字段）
  - `sectionAliases`：区块标题 → 快照区块
  - `scopedAliases`：区块内标签 → 区块字段（解决同名冲突的主力）
  - `optionValueAliases`：快照值 → 页面选项文字（如 `advanced` → `熟练`）
- 目标站 class 名带发版哈希，所有选择器只用前缀匹配（`[class*="title-"]`）

详见 [docs/requirements.md](docs/requirements.md)（含完整需求与决策记录）。
Schema v2 的字段、迁移和 canonical path 见 [docs/schema-v2.md](docs/schema-v2.md)。

## 项目结构

```
extension/
├─ manifest.json      MV3 清单，无构建步骤
├─ lib/               工具函数 / 快照 schema / chrome.storage 封装
├─ rules/seed.json    种子规则库（全局 + Moka/北森/牛客）
├─ content/           detect(服务商识别) scanner(扫描) matcher(匹配)
│                     writer(写入) learn(学回) panel(悬浮球UI) main(编排)
└─ editor/            快照编辑页
```

## 参与贡献

最欢迎的贡献是**规则**：你在某个服务商/某家公司表单上"学"出来的别名规则，整理成 `seed.json` 的 PR，就能让所有人受益。北森、牛客的 DOM 适配（`dom` 配置 + 写入器细节）目前还是空架子，尤其欢迎实测补充。

提交 PR 前请确认：不包含任何个人简历数据；选择器只用 class 前缀匹配。
